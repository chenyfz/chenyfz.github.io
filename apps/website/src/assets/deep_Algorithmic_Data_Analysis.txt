Bernoulli’s Fallacy
The problem scientists face is that they have hypotheses and,
through experiments to test these hypotheses, they have data.
Say we have hypotheses H1 and H2 and a data set D, the
interesting question is:
given D, which of our hypotheses H1 and H2 is more likely?
That is we are interested in P(H1 | D) and P(H2 | D)
▶yet, all statistical tests are based on P(D | H1) and P(D | H2)
These probabilities are, via Bayes, connected, but that requires a
prior on H1 and H2
▶this is subjective and, thus, forbidden territory for many
See, e.g., Bernoulli’s Fallacy; Statistical Illogic and the Crisis of
Modern Science by Aubrey Clayton, Colombia University Press,
2021

Independence
Sometimes conditioning does nothing, this is called independence.
More precisely, two random variables X1 and X2 are independent if,
knowledge of the one doesn’t give you any information about the
other, i.e., if
P(X1|X2) = P(X1)
Note that Bayes law now immediately gives us that
P(X2|X1) = P(X2)
also holds. If X2 gives no information about X1, than X1 can give
you no information about X2.
Another equivalent, again by courtesy of Bayes law, way to
introduce independence is by
P(X1, X2) = P(X1) × P(X2)

Codes
A (binary) code for a countable set X is:
▶a subset C ⊆B∗
▶a relation that associates each x ∈X with one or more code
words c ∈C
▶and a decoding function d : C →X
Note that we do not assume that C has a unique code word for
each x ∈X and we will only use binary codes.
If x ∈X and c ∈C are related, then c is an encoding of x and x is
the decoding of c
The existence of d ensures that a c ∈C encodes just one x ∈X,
i.e., one can decode each code word unambiguously.
The relation between X and C is completely determined by the
decoder function d. Deﬁne the encoding relation
e(x) = d−1(x) = {c ∈C | d(c) = x},

--- Page 6 ---
Preﬁx Codes
A (countable) code C is a preﬁx code if for no two c1, c2 ∈C, c1 is
a proper preﬁx of c2.
One way to think about binary strings is as a path in a binary tree,
where a 0 means branch left and 1 means branch right.
If there is a (possibly inﬁnite) binary tree such that all codes in C
are paths that end in a leaf node of that tree, then C is a preﬁx
code and vice versa.
▶the x ∈X all label one or more of the leafs at the end of a
path encoded by a c ∈C
▶that c is a code for that x.
We can make any code a preﬁx code by making it self-delimiting
▶e.g., by pre-pending the length of the code
▶or by post-pending a special end-of-word code.

--- Page 7 ---

Deﬁne the function

A simple way to do this is to:
▶start the string with ℓ(c) 1’s followed by a 0
▶followed by the actual code c
This is, however, not very eﬃcient, to make C preﬁx, we (more

A Universal Code for the Integers
▶to encode a n ∈N we need log(n) bits – log to base 2
▶to encode log(n) we need log(log(n)) bits
▶to encode log(log(n)) we need log(log(log(n))) bits
▶. . . until log(· · · ) becomes smaller than 1
Risanen: there is a code that uses
k + log∗(n) = k + log(n) + log(log(n)) + · · · bits
A concrete encoding of this type is Elias ω encoding (see
wikipedia). It uses B(n) bits to encode n, where
B(1) = 1
B(n) = ⌊log(n)⌋+ B(⌊log(n)⌋)
= 1 + (1 + ⌊log(n)⌋)) + (1 + ⌊log(log(n))⌋) + · · ·
This is asymptotically optimal

--- Page 9 ---
Elias ω Coding
The encoding algorithm is
1. Place a ”0” at the end of the code.
2. If n = 1, stop; encoding is complete.
3. Prepend the binary representation of n to the beginning of the
code. This will be at least two bits; the ﬁrst bit is a 1.
4. Let n equal the number of bits just prepended, minus one.
5. Return to Step 2 to prepend the encoding of the new n.
Decoding is:
1. Start with a variable n, set to a value of 1.
2. If the next bit is a ”0” then stop. The decoded number is n.
3. If the next bit is a ”1” then read it plus n more bits, and use
that binary number as the new value of n.
4. Go back to Step 2.

Entscheidungsproblem
A challenge posed by David Hilbert and Wilhelm Ackermann in
1928:
Give an algorithm that considers, as input, a statement –
a ﬁrst-order formula – and answers“yes” or “no” according
to whether the statement is universally valid; i.e., true in
all models.
Note that we formulated it anachronistically:
▶the notion of an algorithm did not yet exist.
In fact, one could say that one of the major achievements of
Turing (and Church and ...) was to formalize exactly that notion.
What does a mathematician do when she calculates?
▶she writes down symbols on a sheet of paper based on the
symbols already on that sheet
and that became a Turing machine.

--- Page 7 ---
Turing Machine Informally
A Turing Machine operates on an inﬁnite memory tape divided
into discrete cells, each of which can hold a single symbol drawn
from a ﬁnite set of symbols called the alphabet of the machine. It
has a “head” that, at any point in the machine’s operation, is
positioned over one of these cells, and a “state” selected from a
ﬁnite set of states. At each step of its operation, the head reads
the symbol in its cell. Then, based on the symbol and the
machine’s own present state, the machine writes a symbol into the
same cell, and moves the head one step to the left or the right, or
halts the computation. The choice of which replacement symbol to
write, which direction to move the head, and whether to halt is
based on a ﬁnite table that speciﬁes what to do for each
combination of the current state and the symbol that is read.
source: wikipedia

Turing Machine Formally
A Turing Machine M = ⟨Γ, b, Σ, Q, q0, F, δ⟩, with
▶Γ is a ﬁnite alphabet of symbols
▶b ∈Γ is the blank symbol, the only one that may appear
inﬁnitely often on the input tape
▶Σ ⊆Γ the input symbols (occur on input tape)
▶Q is a ﬁnite set of states
▶q0 ∈Q is the initial state
▶F ⊆Q the ﬁnal or accepting states
▶δ : (Q \ F) × Γ →Q × Γ × {L, R, N} the (partial) transition
function.
We will mostly use the binary alphabet – Γ = {0, 1} – with 0
(often doubling) as the blank symbol.

--- Page 10 ---
The Tape and the Head
The tape t we give to a Turing machine M as input consists of
▶a (ﬁnite) string s ∈Σ∗
▶padded left and right with inﬁnitely many blank symbols, i.e.,
b.
The head is simply an index on t
▶it tells us where on t we are
That is, we do not need a symbol for it, yet having one makes our
lives now and again a bit simpler
▶we use ▷for the head.

--- Page 11 ---
Computing with M
Given an input tape t – a string s from Σ∗padded left and right
with inﬁnitely many b’s – and the “head” of M positioned on the
ﬁrst symbol of s, say s1, M(t) is computed by looking up (q0, s1)
in δ and
▶replace s1 by the symbol from Γ speciﬁed by δ
▶”transition” from state q0 to state qi speciﬁed
▶move the ”head” one symbol to the left, to the right, or keep
it at its current position
And so on and so on
The computation stops when δ speciﬁes no further transition – it is
a partial function. If the current state is a halting state, t (or,
perhaps better, s) was accepted by M, the computation was
successful and the content of the tape is the result.

Universal?
In other words,
▶a Turing machine is simply speciﬁed by a binary string
▶and, obviously, the same holds for a tape.
This suggests that a Turing machine can be input to another
Turing machine.
In turn this raises the question
Does a universal Turing machine, say U exists? That is a
machine U such that for a pair (M, t) of Turing machine
M and tape t we have that
U(M, t) = M(t)
The, in 1936 surprising, answer is: yes!

--- Page 16 ---
Proof Sketch
The crucial observation is U(M, t) = M(t) because we know how
to compute M(t):
▶given the content of the current cell ti (at the position of the
head)
▶and the current state qj
▶look up the (qj, ti) entry in look-up table δ
▶replace ti as speciﬁed
▶replace qj as speciﬁed
▶move the head as speciﬁed
To recall the current qj, ti and so on, we use a one-way inﬁnite
tape (which is equivalent to a two-way inﬁnite tape)
▶and write their representations in a (ﬁnite) buﬀer at the start
of the tape
Matching, copying, and writing are obviously computable actions.

--- Page 17 ---
Some Bookkeeping
To turn the sketch above into a full-ﬂedged proof is basically an
exercise in bookkeeping
▶with special care for the representation of the head symbol
▶it replaces a part of the tape
▶hence that part has to be copied into the buﬀer
▶and put back when the head shifts (in the correct position(s)).
It does not require anything above what a competent programmer
can do
▶but remember, Turing did this before there were any
programmers(!)

--- Page 18 ---
Universal is Universal
If we have two universal Turing machines, U1 and U2
▶then they can emulate each other; they are both universal,
after all
That is, there is a program
▶T1,2 such that U1(T1,2, t) = U2(t) and
▶T2,1 such that U2(T2,1, t) = U1(t)
So, you might think it is far easier to program numerical
computations in, say, Matlab and logical inferences in Prolog than
the other way around
▶but the larger the programs, the less diﬀerence it makes.

--- Page 19 ---
Church Turing Thesis
The fact that one Universal Turing machine can be used to
compute all computable Turing machines and the fact that these
are equivalent to
▶G¨odel and Herbrand’s general recursive functions
▶Church’s λ calculus
▶and unexpected computational models such as Conway’s
game of life (or better, cellular automata)
and the intuitive characterization of “a calculating Mathematician”
by Turing that resulted in Turing machines, gave rise to the
Church Turing thesis
Every eﬀectively calculable function is computable by a
Turing machine

--- Page 20 ---
Universal is both Wonderful and Not
Clearly, the existence of universal Turing machines is wonderful
▶we need only one machine for all possible computations
▶compare this to the number of machines we have to
manipulate matter.
But, there is also a downside
▶because it implies that there are uncomputable things.

The Gambler’s Fallacy
The gambler’s fallacy, also known as the Monte Carlo fal-
lacy or the fallacy of the maturity of chances, is the belief
that, if an event (whose occurrences are independent and
identically distributed) has occurred more frequently than
expected, it is less likely to happen again in the future (or

But are you also aware that (?)
After a consistent tendency towards tails, a gambler may
also decide that tails has become a more likely outcome.
This is a rational and Bayesian conclusion, bearing in mind
the possibility that the coin may not be fair; it is not a fal-
lacy. Believing the odds to favor tails, the gambler sees no
reason to change to heads. However it is a fallacy that a se-

Kolmogorov Complexity
This observation leads to the following deﬁnition:
Choose your favourite universal preﬁx Turing machine U. The
Kolmogorov complexity wrt U of a string x ∈B∗is deﬁned by:
KU(x) = min
p {ℓ(p) | U(p) = x}
where, as before, ℓ(p) denotes the length of p.
Note that we use, as is usual in the literature, Turing machines
that do not use further input. That is, more precisely, we have (for
ϵ the empty string)
U(p, ϵ) = x
which suggest the conditional version of Kolmogorov complexity:
KU(x | y) = min
p {ℓ(p) | U(p, y) = x}

Independence of U
Recall that for two universal machines U1 and U2 we have
programs:
▶T1,2 such that U1(T1,2, t) = U2(t) and
▶T2,1 such that U2(T2,1, t) = U1(t)
This means that there are constants c1,2 and c2,1 such that:
▶∀x ∈B∗: KU1(x) ≤KU2(x) + c1,2
▶∀x ∈B∗: KU2(x) ≤KU1(x) + c2,1
In other words:
|KU1(x) −KU2(x)| ≤c
The Kolmogorov complexity of a string is – upto an additive
constant – independent of the choice for the universal preﬁx Turing
machine.
Because of this, we simply use K (and you can think of your
favourite U)

K is Subadditive
K(xy) ≤K(x) + K(y) + O(1)
Let U be your favourite universal preﬁx Turing machine and let x∗
and y∗be programs for U such that
▶U(x∗) = x and ℓ(x∗) = K(x)
▶U(y∗) = y and ℓ(y∗) = K(y)
Since the set of programs for U is a preﬁx code we can modify U
such that
▶it ﬁrst reads x∗and computes x
▶we know where x∗ends
▶it then reads y∗and computes y
▶we know where y ∗begins (and ends)
▶and then it prints xy
This modiﬁcation of U is a (short) program that is independent of
x, x′, y and y′ – it is a constant.

An Upperbound
As we noted before, we can recode all binary strings as a preﬁx
code, by preﬁxing each string with its length, i.e.,
▶for x ∈B∗deﬁne ¯x = 1ℓ(x)0x
▶and, thus, ℓ(¯x) = 2ℓ(x) + 1

ℓ(x)x (and the 1 extra bit, of course)

produces x and K(x) is the length of the shortest such program.

The Problem

The Bayesian Approach
The problem is simple to formalize:
▶what is the probability of symbol a after we have seen
x1 · · · xn?
That is,
P(x1 · · · xna | x1 · · · xn)
Bayes tells us that
P(x1 · · · xna | x1 · · · xn) = P(x1 · · · xna)
P(x1 · · · xn)
The problem is, thus,
what is P(x) for some string x?
For simplicity, but without loss of generality, we will consider
binary strings only

Inﬁnite Bit Strings
Until now we relied on ﬁnite bit strings, i.e., elements of B∗.
Clearly, all bit strings we will ever encounter in sequence prediction
will be ﬁnite as well.
But note that the string we want to learn might be one way

we are trying to learn π.
These one way inﬁnite strings are the elements of
B∞

of the (inﬁnite) string.

A Sigma Algebra on B∞
We want to deﬁne P(x) for x ∈B∞(as well as for x ∈B∗. For
that we need a sigma algebra on B∞. This means that we need a
set of events.
Note that P(B∞) is not countable, so we use a restricted set of
subsets, the set of cylinders. For x ∈B∗, the cylinder
Γx = {xω | ω ∈B∞}
Furthermore, G = {Γx | x ∈B∗}
Clearly G is not a sigma algebra either, but it extends into one by
adding unions and intersections. Since we only use probabilities of
cylinders, we will leave this extension implicit.
