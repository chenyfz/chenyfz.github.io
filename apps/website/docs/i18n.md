# Internationalization (i18n)

This project uses a minimal i18n setup for a static Astro site.

## Behavior

- Supported locales: `en`, `zh`.
- Only the root route (`/`) performs locale detection.
- Detection rule: if system/browser language contains Chinese (`zh*`), redirect to `/zh/`; otherwise redirect to `/en/`.
- No locale is persisted to `localStorage`.
- Localized routes (e.g. `/en/...`, `/zh/...`) render directly and do not run extra i18n side effects.

## File Responsibilities

- `src/i18n/config.ts`
  - Locale constants and shared helpers (`locales`, `defaultLocale`, param validation).
- `src/i18n/t.ts`
  - Tiny helper to pick localized data from `{ en, zh }` maps.
- `src/components/LocaleRedirect.astro`
  - Root-only redirect component (`/` -> `/en/` or `/zh/`).
- `src/i18n/pages/<page>/en.ts` and `src/i18n/pages/<page>/zh.ts`
  - Per-page localized content.

## Adding a New Localized Page

1. Create content files:
   - `src/i18n/pages/<page>/en.ts`
   - `src/i18n/pages/<page>/zh.ts`
2. Create route file:
   - `src/pages/[lang]/<page>.astro`
3. In the route file:
   - use `locales.map((lang) => ({ params: { lang } }))`
   - use `requireLocaleParam(Astro.params.lang)`
   - use `t({ en, zh }, locale)` to read localized content

## Adding a New Language

1. Add locale in `src/i18n/config.ts`.
2. Add the new locale file for each page (e.g. `ja.ts`).
3. Update each page route map passed to `t(...)`.
4. Run `pnpm build`.
