Introduction 
The goal of this assignment is to experiment with acceleration structures.  
Based on Jacco Bikker’s online tutorial (with code on Github) or his more recent implementation, 
adding a BVH to an existing ray tracing-based renderer (possibly your own) should be trivial. 
For this assignment, you will be analyzing the characteristics of the BVH and compare it to other 
acceleration structures. 
Acceleration Structures 
In the lectures we discussed a number of acceleration structures, each with their own characteristics:  
• 
Grid 
• 
kD-tree 
• 
Octree 
• 
BSP 
More options exist, such as tetrahedralization, loose grids, the Bounding Interval Hierarchy and so 
on. We can compare data structures on various characteristics:  
• 
Construction speed (in terms of algorithmic complexity or actual wall-clock time)  
• 
Speed of various types of updates (rigid motion, deformation, full rebuild) 
• 
Ray tracing efficiency  
For this assignment we ask you to focus on the ray tracing efficiency. This is the one that can be 
made independent of implementation quality, which is beneficial for a time-constrained assignment. 
To compare ray tracing efficiency, we could use wall-clock time but that depends on your choice of 
programming language, compiler, low-level optimizations, etc. To make it a fair challenge, we will 
instead compare the number of traversal steps and number of intersection tests encountered 
during ray traversal.

Optimizing Ray Tracing
Options:
1. Faster intersections (reduce cost per ray & per primitive)
2. Faster shading (reduce cost per ray)
3. Use more expressive primitives (trade off #primitives, intersection cost, algorithmic complexity)
4. Fewer ray/primitive intersections (trade off total intersection cost, algorithmic complexity)
Note for option 1:
At 5 billion ray/primitive intersections, we will have to bring down the cost of a single intersection to 
1 cycle on a 5Ghz CPU – if we want one frame per second.

kD-Tree Construction*
A kd-tree is a binary tree that recursively subdivides the space 
occupied by the scene.
▪The root corresponds to the axis aligned bounding box (AABB) 
of the scene;
▪Interior nodes represent planes that recursively subdivide space 
perpendicular to the coordinate axis;
▪Leaf nodes store references to all the triangles overlapping the 
corresponding voxel.
*: On building fast kD-trees for ray tracing, and on doing that in O(N log N), Wald & Havran, 2006

Traversal – Alternative Method*
For interior nodes:
1. Determine ‘near’ and ‘far’ child node
2. Determine if ray intersects ‘near’ and/or ‘far’
If only one child node intersects the ray:
▪
Traverse the node (goto 1)
       Else (both child nodes intersect the ray):
▪Push ‘far’ node to stack
▪Traverse ‘near’ node (goto 1)
For leaf nodes:
1. Determine the nearest intersection
2. Return if intersection is inside the voxel.
*: Data Structures for Ray Tracing, Jansen, 1986.

As 𝑁 approaches infinity, the Monte Carlo sum approaches the

Divide the whole domain into pieces, calculate a function value in

Take some random samples from the whole domain, calculate the
